## Revised Cache Policy Section

**What is currently implemented:**

- **Slot interval:** 5-minute UTC minute slots (REUSE_MINUTES = 5)
- **Revalidation:** Next.js cache.revalidate = 300 seconds (REUSE_INTERVAL_MS / 1000)
- **Freshness marker:** Data shown as "stale" after 15 minutes (FRESHNESS_MS = 15 * 60_000)
- **Window roll:** Data also marked stale when selected window rolls forward past endUtcExclusive
- **Error persistence:** Failed responses are cached for the slot duration

**What this means for Evidence Trail:**

| Scenario | Cache Behavior | User Visibility |
| --- | --- | --- |
| Request at 15:02 UTC (slot start 15:00) | Fetches NOAA, caches result | "New response from NOAA" |
| Request at 15:05 UTC (same slot) | Returns cached result | "Reused a cached NOAA response" |
| Request at 15:07 UTC (same slot) | Cache revalidate = 300s not yet expired; still cached | "Reused a cached NOAA response" |
| Request at 15:10 UTC (next slot 15:10) | Fetches fresh NOAA | "New response from NOAA" |
| View persists 15 min without refresh | Same snapshot, now stale | "The displayed response is stale. Check for an updated window." |
| User changes time window | New fetch regardless of cache | Triggers new cache cycle |

**What is NOT captured:**

- Cache hit rate metrics
- NOAA server-side cache headers (Cache-Control, ETag, etc.)
- Request concurrency or "in-flight" behavior (tracked in-memory, not persistent)
- Historical cache performance or miss reasons
